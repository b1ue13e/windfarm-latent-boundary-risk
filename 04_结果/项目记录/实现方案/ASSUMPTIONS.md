# Assumption Ledger — Metis E04 Receipt/Hash Binding

| ID | Under-determined by the request | Chosen | Class | Source |
|----|--------------------------------|--------|-------|--------|
| A-001 | The request does not name the binding boundary | Bind each E04 run's declared inputs and all five policy-array outputs to a receipt, then bind the selector JSON to the same receipt and manifest | semantic | default |
| A-002 | The request does not specify whether existing v4 arrays may be promoted | Existing arrays remain historical/untrusted unless accompanied by a newly generated valid receipt; no retroactive receipt is fabricated | semantic | default |
| A-003 | The request does not specify how hashes are represented | SHA-256 file records with byte count and resolved path; manifest hash is the hash of canonical JSON bytes written by the utility | interface | default |
| A-004 | The request does not specify failure behavior | Missing, changed, extra, or receipt-mismatched files raise a hard error before selection | semantic | default |
| A-005 | The request does not specify the command working directory | Default to the caller's current directory; allow an explicit `--working-dir` and record it in the frozen plan metadata | interface | default |

## Notes

- **A-001:** The current defect is not an absent digest primitive; it is the missing relation between process receipt, declared inputs, output manifest, and selector result.
- **A-002:** A receipt is evidence of a run only when generated by the run wrapper. Existing arrays are not retroactively certified by this patch.
- **A-004:** Hard failure preserves the current scientific claim ceiling and prevents a provenance failure from becoming a numeric result.
